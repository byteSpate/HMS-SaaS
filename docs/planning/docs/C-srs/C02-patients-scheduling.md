## 1. Purpose and scope

Find or register the right patient once, keep one identity per tenant, and turn arrivals into visits. Arrivals are booked appointments, walk-ins or direct diagnostic arrivals. Includes the practitioner directory and doctor schedules.

## 2. Actors

Receptionist, doctor (books a next visit), hospital administrator (masters, identity edits), emergency staff (temporary identity, C10).

## 4. Use cases

### UC-PAT-01 Search and register a patient

- **Actor / permission:** receptionist (`patient.record.search`, `patient.record.register`).
- **Trigger:** a patient arrives at the front desk.
- **Inputs:** a search term (name in either script, MRN, phone in any format, NID); registration fields per FR-PAT-005/CP-10; idempotency key.
- **Normal path:**
  1. The receptionist types a term. The server returns up to 20 ranked matches with banner fields.
  2. No match → the receptionist opens registration with the search term prefilled.
  3. While typing, the UI requests duplicate candidates (FR-PAT-011) after name + sex + age/birth date are present.
  4. The receptionist reviews the candidates (none shown in this path) and submits.
  5. The server validates, generates the MRN, creates the patient and writes an audit event.
  6. The UI shows the patient banner and offers "Book appointment", "Walk-in visit" or "Diagnostic visit".
- **Outputs:** `patient`, `patient_identifier` (MRN; NID if given), audit event `patient.registered`, outbox event `PatientRegistered`.
- **Alternative paths:**
  - A1: a candidate is the same person → the receptionist selects it. No new patient is created.
  - A2: the receptionist believes the candidate is a different person → confirms "Register as new". The confirmation and the shown candidate IDs are recorded in the audit event.
  - A3: the patient knows only their age → FR-PAT-006.
- **Denied paths:** D1: the user lacks `patient.record.register` → search works, but registration is hidden and refused by the server (SP-04).
- **Cancellation:** C1: the receptionist abandons the form → nothing is saved (SP-12).
- **Recovery:** R1: the response times out → the UI retries with the same idempotency key (SP-08). The server returns the same patient and MRN.
- **Requirements:** FR-PAT-001..003, FR-PAT-005, FR-PAT-006, FR-PAT-009, FR-PAT-011.

### UC-PAT-02 Correct patient identity details

- **Actor:** `patient.identity.edit`.
- **Preconditions:** the patient exists in the tenant.
- **Normal path:**
  1. Open the patient.
  2. Edit the allowed fields.
  3. Enter a mandatory reason.
  4. Submit with the expected version.
  5. The server stores the new values and an identity-history row with the previous values. It audits the change and emits `PatientIdentityChanged`.
- **Denied paths:**
  - D1: stale version (SP-03).
  - D2: attempt to change MRN → not editable (`VALIDATION_FAILED`).
- **Requirements:** FR-PAT-008.

### UC-PAT-03 Reconcile a temporary identity (OPEN procedure)

- **Status:** the capability is CONFIRMED; the procedure is OPEN (Q-036). **Interim:** not implemented. A temporary patient keeps its MRN, and staff record the real identity in that same record using UC-PAT-02 (permission-gated, audited). Linking two existing records waits for Q-036.

### UC-SCH-01 Book an appointment

- **Actor:** `scheduling.appointment.book`.
- **Preconditions:** the patient exists. The practitioner session is published and in the future.
- **Normal path:**
  1. Select practitioner, date and session.
  2. The server shows remaining capacity.
  3. Select a slot or session.
  4. Submit.
  5. The server checks capacity transactionally and creates `appointment(BOOKED)`.
  6. Optionally print an appointment slip (A5).
- **Alternative paths:** A1: book as "next visit" from a visit → the appointment stores `follow_up_of_visit_id`.
- **Denied paths:**
  - D1: capacity full → `CAPACITY_FULL`; the UI suggests the next sessions with capacity.
  - D2: session in the past → `VALIDATION_FAILED`.
- **Recovery:** SP-01, SP-08.
- **Requirements:** FR-SCH-002, FR-SCH-003, FR-SCH-006.

### UC-SCH-02 Reschedule or cancel an appointment

- **Normal path (reschedule):**
  1. Select a new session.
  2. The server, in one transaction, books the new appointment (capacity check), marks the old one `RESCHEDULED` and links them.
- **Cancellation path:** set `CANCELLED` with a reason. The capacity is released.
- **Denied paths:** D1: the appointment is already `CHECKED_IN` → `INVALID_TRANSITION`. The visit must be handled instead.
- **Requirements:** FR-SCH-002.

### UC-VIS-01 Check in an appointment

- **Actor:** `visit.checkin`.
- **Preconditions:** the appointment is `BOOKED` and its date is today (in facility timezone). Early or late check-in tolerance is configurable (PROPOSED).
- **Normal path:**
  1. Find the appointment by patient or list.
  2. Check in with the appointment's expected version and an idempotency key.
  3. The server, in one transaction:
     - sets the appointment to `CHECKED_IN`
     - creates the `visit(OPD_CONSULTATION, OPEN)`
     - assigns the queue number
     - requests the doctor-fee invoice from billing (FR-BIL-010)
     - writes outbox `VisitCheckedIn`
  4. The UI shows the visit with "Doctor fee invoice D: due 500.00" (synthetic) and a shortcut to the cashier queue.
- **State transitions:** appointment `BOOKED → CHECKED_IN`; visit created `OPEN`; invoice D `ISSUED`.
- **Alternative paths:** A1: the doctor fee is not configured for the practitioner → the visit is still created; the invoice is not issued; the UI shows `POLICY_NOT_CONFIGURED` for the fee and alerts the administrator. (Consultation cannot start without the invoice being paid unless policy says otherwise; see C03.)
- **Denied paths:**
  - D1: appointment `CANCELLED`/`NO_SHOW` → `INVALID_TRANSITION`.
  - D2: another tenant's appointment ID → `NOT_FOUND`.
- **Recovery:**
  - R1: double click → one visit (SP-01).
  - R2: two receptionists check in the same appointment concurrently → one succeeds; the other gets the same visit (same key) or `STALE_RECORD` (different key).
- **Requirements:** FR-SCH-001, FR-VIS-002, FR-VIS-004, FR-VIS-005, FR-SCH-004.

### UC-VIS-02 Create a walk-in or direct diagnostic visit

- **Actor:** `visit.create`; for diagnostic orders, also `order.direct_diagnostic.create`.
- **Normal path (walk-in OPD):** select the patient, practitioner and session → create `visit(OPD_CONSULTATION)` → queue number → doctor-fee invoice (as in UC-VIS-01).
- **Normal path (diagnostic):**
  1. Select the patient.
  2. Choose "Diagnostic visit".
  3. Pick tests from the **directly orderable** list (CP-01).
  4. The server creates `visit(DIAGNOSTIC)` and orders (FR-ORD-001), and adds the service invoice lines (FR-BIL-009).
- **Denied paths:** D1: a test not directly orderable → `PERMISSION_DENIED` with reason `TEST_NOT_DIRECTLY_ORDERABLE`. The UI never lists such tests in the direct-order picker.
- **Requirements:** FR-VIS-001, FR-ORD-001, FR-BIL-009.

## 5. State machines

**Appointment states and transitions:**

| From | To | Trigger |
| --- | --- | --- |
| (new) | `BOOKED` | Book |
| `BOOKED` | `CHECKED_IN` | Check-in (creates the visit) |
| `BOOKED` | `RESCHEDULED` | Reschedule (creates a new linked appointment) |
| `BOOKED` | `CANCELLED` | Cancel (reason) |
| `BOOKED` | `NO_SHOW` | Mark no-show (after the session end) |

`CHECKED_IN`, `RESCHEDULED`, `CANCELLED` and `NO_SHOW` are terminal.

**Visit:** `OPEN → COMPLETED | CANCELLED` (FR-VIS-003).

**Patient identity status:** `TEMPORARY → CONFIRMED` (by UC-PAT-02 completing the required fields), `CONFIRMED → MERGED_INTO` (only after Q-036; not implemented).

## 6. Fixed rules versus configurable policy

| Fixed | Configurable |
| --- | --- |
| MRN unique per tenant; never changes | MRN pattern (CP-09) |
| Search before register; no auto-merge | Required fields (CP-10) |
| Booking ≠ visit | Capacity, overbooking, queue numbering (CP-11) |
| One visit per appointment check-in | Check-in tolerance window |
| Practitioner name is not a unique key | Duplicate-match threshold (tuning, not policy) |

```gherkin
  Given no patient named "Salma Begum" exists

  Given Salma Begum has an appointment with Dr. Hasan for Tuesday
  When Tuesday's doctor worklist is loaded before check-in
  Then Salma Begum is listed under "Expected" and not under "Arrived"
  And no visit and no invoice exists

  Given Dr. Hasan's Tuesday morning session has 1 slot left
  When two receptionists book different patients at the same moment
  Then exactly one booking succeeds
  And the other receives CAPACITY_FULL

Scenario: Diagnostic visit without consultation (FR-VIS-001, FR-ORD-001)
  Given test "CBC" is directly orderable and "Thyroid panel" is not
  When reception creates a diagnostic visit for Karim Ahmed with CBC
  Then the visit is created with kind DIAGNOSTIC and no doctor-fee invoice
  And attempting to add "Thyroid panel" returns PERMISSION_DENIED
```
