## 1. Method and coverage

1. **Inventory:** every URL from each site's sitemap (Continental, Evercare, Popular, Ibn Sina) or, without a sitemap, by crawling the site's own links two levels deep (Square, Labaid). 5,677 URLs in total.
2. **Page types:** URLs grouped by route pattern. Every unique page was analyzed; repeated collections (doctor profiles, blogs, departments) were sampled with 3 pages each, because they share one template.
3. **Capture:** each of the 264 representative pages was loaded in a headless Chromium. REA `capture-browser-scenario` recorded every network request and response structure (JSON field names only, values discarded); a separate pass extracted headings, forms, inputs, buttons and text.

## 6. Lessons (what not to copy)

- **Secrets in public URLs:** Square sends a fixed key in its appointment-dates API path, and Popular sends a static token with every API call. Anything sent to the browser is public; HMS public read APIs need no secret and are rate limited (D section 11).
- **Report-only CSP** (Continental) and **ad-tracker load on a health site** (Evercare loads Google Ads conversion and DoubleClick on every page, including appointment forms). HMS: enforced CSP, no ad trackers in WEB-A, consent before any analytics (Q-076).
- **Patient data in browser storage** (Continental caches the patient profile in `localStorage`).
- **Phone-only portal login** (Continental). HMS FR-POR-001 requires verified linking (Q-033).
- **Legacy stacks** (PHP 7.3, mixed PHP and WordPress) make editing slow and unsafe; this is the gap the HMS website CMS (C-072) fills.
