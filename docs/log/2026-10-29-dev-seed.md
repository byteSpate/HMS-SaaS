# Development seed: demo hospital, administrator and receptionist

- **Date:** 2026-10-29
- **Commit:** this commit
- **Implements:** local manual testing of T-ACC-03..05 (owner request 2026-10-29); C-045; AS-009

## What was built

`pnpm db:seed:dev` fills a fresh local database so the staff app can be tried by hand. It creates the hospital "Demo Hospital" (`code: demo`, ACTIVE) with the nine template roles (C-045), and two users:

| Username    | Password             | Role               | What it shows                                |
| ----------- | -------------------- | ------------------ | -------------------------------------------- |
| `admin`     | `Admin-dev-2026`     | ADM, administrator | MFA set-up on first login, Users and Roles   |
| `reception` | `Reception-dev-2026` | RCP, receptionist  | A normal staff login without a second factor |

Running it again changes nothing (it stops when `admin` exists). It refuses any `DATABASE_URL` whose host is not `localhost` or `127.0.0.1`.

## Decisions applied

- The script lives in `apps/api`, which already depends on `@hms/database` and `@hms/mod-identity-access`, so `pnpm boundaries:check` is unaffected and no package gains a dependency.
- Passwords are hashed before the `withTenant` transaction, because argon2 is slow and the transaction allows 5 seconds.
- The demo passwords are synthetic, like the values in `.env.example`; the `sonarjs/no-hardcoded-passwords` rule is disabled only around that constant, with the reason.
- Users are not marked `mustChangePassword`, so the first login goes straight to the MFA step for `admin`; the forced change is tested with a user the administrator creates.

## Known limitations

- The script is not covered by `pnpm typecheck` or `pnpm lint` in CI (they check `src` only); the commands above were run by hand.
- It imports the built `dist` of the workspace packages, so run `pnpm build` (or `pnpm dev` once) before the first seed.
- No entitlements are seeded; only core-module routes (all of authentication and administration) are reachable.

## Deploy impact

None. Development-only script; nothing runs it on a server.

## How to debug

- **`Refusing to seed a non-local database`:** `.env` points at a remote database; the seed is for local Docker only.
- **`Cannot find module .../dist/index.js`:** build the packages first (`pnpm build`).
- **Start over:** `pnpm services:down`, `docker volume rm hms-dev_pgdata-dev`, `pnpm services:up`, `pnpm db:deploy`, `pnpm db:seed:dev`.
- **API refuses to start with `MFA_ENCRYPTION_KEY must be 32 bytes`:** an older `.env` lacks the T-ACC-04 variables; copy `MFA_ENCRYPTION_KEY`, `LOGIN_LOCKOUT_ATTEMPTS` and `LOGIN_LOCKOUT_MINUTES` from `.env.example`.
- **Browser writes answer `403 CSRF_TOKEN_INVALID`:** `CORS_ORIGINS` in `.env` must include `http://localhost:3000` (the dev proxy).
